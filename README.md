# Get Started
## Database
- Download Postgres (i.e the database that Mealbot uses) [here](https://www.postgresql.org/download/). See link for specific instructions for your OS.
- Create a Postgres database and set `DB_USER` / `DB_NAME` (or `DATABASE_URL`, see below) to point to it
- Setup the database schema by executing `schema.sql` (note: it drops and recreates the tables)
- NOTE: If the steps above for the database aren't super clear, please check out official Postgres documentation. For help on SQL syntax, check out [PostgreSQL Tutorial](http://www.postgresqltutorial.com/)

## Go
- Fetch dependencies and generate `go.sum`: `go mod tidy` (needed once after pulling; `go.sum` is regenerated by it)
- Build the server: `go build -o bin/mealbot ./cmd/mealbot` (the build target is `./cmd/mealbot`; the Procfile runs `bin/mealbot`)
- Run the server: `./bin/mealbot` (listens on `$PORT`, default 8080)
- Run the pairing scheduler: `./bin/mealbot pair`
- Run the 'last round with' migration: `./bin/mealbot migrate`
- Health check (no authentication, no database needed): `curl localhost:8080/healthz` returns `{"status":"ok"}`
- All other API routes require an Auth0 bearer token (RS256, matching issuer and audience); requests without a valid token get HTTP 401.

## Tests and linting
- `go test -race ./...`
- Integration tests (`internal/store`, `internal/httpapi/handlers`, `internal/pairing`) start Postgres with testcontainers-go and apply `schema.sql`. They are skipped automatically when Docker is not available.
- `go vet ./...` and `golangci-lint run` (see `.golangci.yml`)

## Configuration (environment variables)
| Variable | Default | Purpose |
| --- | --- | --- |
| `PORT` | `8080` | HTTP listen port |
| `DATABASE_URL` | (unset) | Postgres URL (set by Heroku). When unset, `DB_USER`/`DB_NAME` are used |
| `DB_USER` | `johnamadeodaniswara` | Local database user |
| `DB_NAME` | `mealbot` | Local database name |
| `AUTH0_ISSUER` | `https://mealbot.auth0.com/` | Expected JWT `iss` |
| `AUTH0_AUDIENCE` | `https://mealbot-2.herokuapp.com/` | Expected JWT `aud` |
| `AUTH0_JWKS_URL` | `https://mealbot.auth0.com/.well-known/jwks.json` | JWKS used to verify tokens (cached) |
| `MAILGUN_DOMAIN` | (unset) | Mailgun domain (required to send pairing emails) |
| `MAILGUN_API_KEY` | (unset) | Mailgun API key (required to send pairing emails) |
| `MAILGUN_SMTP_LOGIN` | (unset) | Sender address of pairing emails |
| `LOG_LEVEL` | `info` | `debug`, `info`, `warn` or `error` |
| `STATIC_DIR` | `./static` | Directory served at `/` |
| `CSV_DIR` | `./csv/` | Where uploaded member CSVs are stored |

## Layout
- `cmd/mealbot`: entry point (server, `pair`, `migrate`)
- `internal/config`, `internal/logging` (slog), `internal/db` (pgx pool, JSONB helpers), `internal/store` (raw SQL), `internal/auth` (JWT/JWKS), `internal/httpapi` (+ `handlers`), `internal/pairing`, `internal/mail` (Mailgun behind a `Mailer` interface)

## Docker (optional)
`docker build -t mealbot .` then `docker run -p 8080:8080 -e DATABASE_URL=... mealbot`
